## Worker 进程机制

### 1.1 Worker 启动方式

Worker 进程通过 `surreal_commands` 库提供的 CLI 工具启动。

**Makefile 定义** (`Makefile:140-168`):

```makefile
worker: worker-start

worker-start:
	@echo "Starting surreal-commands-worker..."
	uv run --env-file .env surreal-commands-worker --import-modules commands

worker-stop:
	@echo "Stopping surreal-commands-worker..."
	pkill -f "surreal-commands-worker" || true

# 完整启动流程
start-all:
	@echo "🚀 Starting Open Notebook..."
	@docker compose -f docker-compose.dev.yml up -d surrealdb
	@uv run run_api.py &
	@uv run --env-file .env surreal-commands-worker --import-modules commands &
	cd frontend && npm run dev
```

### 1.2 关键启动参数解析

| 参数 | 值 | 作用 |
|------|-----|------|
| `--env-file .env` | - | 加载环境变量（数据库连接、API 密钥等） |
| `surreal-commands-worker` | - | `surreal_commands` 库提供的 Worker CLI |
| `--import-modules commands` | `commands` | 指定要导入的 Python 模块路径 |

### 1.3 Worker 工作原理

`surreal-commands-worker` 是一个独立的进程，其核心工作流程：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                     surreal-commands-worker 进程                              │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │  1. 初始化阶段                                                         │  │
│  │     ├── 导入 --import-modules 指定的模块 (commands)                   │  │
│  │     ├── 触发模块中的 @command 装饰器执行                                │  │
│  │     └── 所有命令函数注册到全局注册表                                    │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                    │                                         │
│                                    ▼                                         │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │  2. 主循环 (Main Loop)                                                 │  │
│  │     while True:                                                        │  │
│  │       ┌────────────────────────────────────────────────────────────┐  │  │
│  │       │ 2.1 轮询数据库: SELECT * FROM command                       │  │  │
│  │       │     WHERE status IN ['queued', 'retry']                     │  │  │
│  │       │     ORDER BY created ASC                                     │  │  │
│  │       └────────────────────────────────────────────────────────────┘  │  │
│  │                                    │                                     │  │
│  │                                    ▼                                     │  │
│  │       ┌────────────────────────────────────────────────────────────┐  │  │
│  │       │ 2.2 找到待处理命令?                                          │  │  │
│  │       │     ├── 否: sleep 1~5 秒 (指数退避)                        │  │  │
│  │       │     └── 是: 更新状态为 'running'，开始执行                   │  │  │
│  │       └────────────────────────────────────────────────────────────┘  │  │
│  │                                    │                                     │  │
│  │                                    ▼                                     │  │
│  │       ┌────────────────────────────────────────────────────────────┐  │  │
│  │       │ 2.3 执行命令                                                 │  │  │
│  │       │     ├── 从注册表查找 app.command 对应的函数                  │  │  │
│  │       │     ├── 反序列化 input 参数为 CommandInput 子类             │  │  │
│  │       │     ├── 注入 execution_context (包含 command_id)            │  │  │
│  │       │     └── 调用实际的命令函数                                   │  │  │
│  │       └────────────────────────────────────────────────────────────┘  │  │
│  │                                    │                                     │  │
│  │                                    ▼                                     │  │
│  │       ┌────────────────────────────────────────────────────────────┐  │  │
│  │       │ 2.4 更新结果                                                 │  │  │
│  │       │     ├── 成功: status='completed', result=输出               │  │  │
│  │       │     ├── 失败: status='failed', error_message=错误信息       │  │  │
│  │       │     └── 可重试失败: 根据策略更新重试次数，状态='retry'       │  │  │
│  │       └────────────────────────────────────────────────────────────┘  │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 命令分发与路由

### 2.1 命令注册机制

命令通过 `@command` 装饰器在模块导入时自动注册。

**示例：Source 处理命令** (`commands/source_commands.py:49-60`):

```python
from surreal_commands import CommandInput, CommandOutput, command

class SourceProcessingInput(CommandInput):
    source_id: str
    content_state: Dict[str, Any]
    notebook_ids: List[str]
    transformations: List[str]
    embed: bool

class SourceProcessingOutput(CommandOutput):
    success: bool
    source_id: str
    embedded_chunks: int = 0
    insights_created: int = 0
    processing_time: float
    error_message: Optional[str] = None

@command(
    "process_source",           # 命令名称
    app="open_notebook",        # 应用标识（用于命名空间隔离）
    retry={                     # 重试策略配置
        "max_attempts": 15,
        "wait_strategy": "exponential_jitter",
        "wait_min": 1,
        "wait_max": 120,
        "stop_on": [ValueError, ConfigurationError],  # 遇到这些错误不重试
    },
)
async def process_source_command(
    input_data: SourceProcessingInput,
) -> SourceProcessingOutput:
    # 实际业务逻辑...
    pass
```

### 3.2 状态流转图

```
                    ┌─────────────────────────────────────────────────────┐
                    │                    状态流转                            │
                    └─────────────────────────────────────────────────────┘

  submit_command()        Worker pickup          执行成功
       │                      │                      │
       ▼                      ▼                      ▼
┌──────────┐           ┌──────────┐           ┌───────────┐
│  queued  │──────────▶│ running  │──────────▶│ completed │
└──────────┘           └──────────┘           └───────────┘
       │                      │
       │                      │ 执行失败
       │                      ▼
       │               ┌──────────┐
       │               │  failed  │◀────────── 不可重试错误
       │               └──────────┘
       │                      │
       │                      │ 可重试错误 (未达最大次数)
       │                      ▼
       │               ┌──────────┐
       └──────────────▶│  retry   │──────────▶ 重新进入 queued 状态
                       └──────────┘
```

### 3.3 状态定义

| 状态 | 含义 | 触发条件 |
|------|------|---------|
| `queued` | 已入队，等待处理 | `submit_command()` 创建时 |
| `running` | 正在执行 | Worker pickup 后 |
| `completed` | 执行成功 | 命令函数正常返回 |
| `failed` | 执行失败 | 抛出不可重试异常，或重试耗尽 |
| `retry` | 等待重试 | 抛出可重试异常，且未达最大次数 |

**领域模型封装** (`open_notebook/domain/notebook.py:318-359`):

Source 模型提供便捷的状态查询方法：

```python
async def get_status(self) -> Optional[str]:
    """Get the processing status of the associated command"""
    if not self.command:
        return None

    try:
        from surreal_commands import get_command_status

        status = await get_command_status(str(self.command))
        return status.status if status else "unknown"
    except Exception as e:
        logger.warning(f"Failed to get command status for {self.command}: {e}")
        return "unknown"

async def get_processing_progress(self) -> Optional[Dict[str, Any]]:
    """Get detailed processing information for the associated command"""
    if not self.command:
        return None

    try:
        from surreal_commands import get_command_status

        status_result = await get_command_status(str(self.command))
        if not status_result:
            return None

        result = getattr(status_result, "result", None)
        execution_metadata = (
            result.get("execution_metadata", {}) if isinstance(result, dict) else {}
        )

        return {
            "status": status_result.status,
            "started_at": execution_metadata.get("started_at"),
            "completed_at": execution_metadata.get("completed_at"),
            "error": getattr(status_result, "error_message", None),
            "result": result,
        }
    except Exception as e:
        logger.warning(f"Failed to get command progress for {self.command}: {e}")
        return None
```

### 4.1 状态轮询机制

前端使用 **React Query** (`@tanstack/react-query`) 实现自动轮询。

**Hook 定义** (`frontend/src/lib/hooks/use-sources.ts:234-259`):

```typescript
export function useSourceStatus(sourceId: string, enabled = true) {
  return useQuery({
    queryKey: ['sources', sourceId, 'status'],
    queryFn: () => sourcesApi.status(sourceId),
    enabled: !!sourceId && enabled,
    
    // 智能轮询间隔
    refetchInterval: (query) => {
      const data = query.state.data as SourceStatusResponse | undefined
      // 处理中: 每2秒轮询一次
      if (data?.status === 'running' || data?.status === 'queued' || data?.status === 'new') {
        return 2000
      }
      // 完成/失败: 停止轮询
      return false
    },
    
    staleTime: 0,  // 状态数据始终视为过期，需要实时更新
    
    // 重试策略
    retry: (failureCount, error) => {
      const axiosError = error as { response?: { status?: number } }
      if (axiosError?.response?.status === 404) {
        return false  // 404 不重试
      }
      return failureCount < 3
    },
  })
}
```

// 追踪处理状态，检测完成
useEffect(() => {
  const currentStatusFromData = statusData?.status || sourceWithStatus.status

  // 如果正在处理，标记 wasProcessing = true
  if (currentStatusFromData === 'new' || 
      currentStatusFromData === 'running' || 
      currentStatusFromData === 'queued') {
    setWasProcessing(true)
  }

  // 如果之前在处理，现在完成/失败了:
  // 1. 停止轮询

  if (wasProcessing &&

    if (onRefresh) {
      setTimeout(() => onRefresh(), 500)  // 延迟刷新，确保 API 数据已更新
    }
  }
}, [statusData, sourceWithStatus.status, wasProcessing, onRefresh, source.id])

## 总结

### 核心机制

1. **Worker 进程独立**: `surreal-commands-worker` 是独立进程，通过轮询 SurrealDB 获取任务
2. **装饰器注册**: `@command` 装饰器在模块导入时自动注册命令到全局注册表
3. **状态驱动**: 所有状态流转都通过数据库 `command` 表持久化
4. **智能轮询**: 前端 React Query 只在处理中时轮询，完成后自动停止
5. **实时反馈**: UI 根据状态显示不同图标、颜色、消息，支持进度条和重试

### 设计优势

1. **解耦**: 前端请求与后端处理完全解耦，不阻塞 HTTP 请求
2. **可靠**: 支持重试机制，transient error 自动恢复
3. **可观测**: 所有状态都持久化到数据库，可随时查询
4. **用户体验**: 实时状态反馈 + 失败重试功能
5. **可扩展**: Worker 进程可独立水平扩展

本篇报告是 [命令面板前后端调用分析.md](./命令面板前后端调用分析.md) 的深入补充：
