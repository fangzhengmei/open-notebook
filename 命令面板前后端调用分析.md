## 概述

Open Notebook 项目中存在两个不同层次的"命令"概念：

1. **前端 CommandPalette 组件**：纯前端 UI 组件，用于快速导航和本地操作
2. **后端命令系统**：基于 `surreal_commands` 库的异步任务队列系统，用于执行耗时操作

本报告主要分析**后端命令系统**的前后端调用流程，这是真正跨越前后端的命令执行机制。

## 前端架构

### 1. API 客户端层

**文件**: `frontend/src/lib/api/client.ts`

前端使用 Axios 作为 HTTP 客户端，核心配置：

```typescript
export const apiClient = axios.create({
  timeout: 600000, // 10分钟超时，适配 LLM 慢操作
  headers: {
    'Content-Type': 'application/json',
  },
  withCredentials: false,
})
```

**请求拦截器**负责：
- 动态获取 API 基础 URL（通过 `getApiUrl()`）
- 从 localStorage 读取认证 token 并添加 `Authorization` 头
- 自动处理 FormData 与 JSON 的 Content-Type 切换

**响应拦截器**负责：
- 401 状态时自动清除认证状态并重定向到登录页

### 2. 业务 API 封装

**文件**: `frontend/src/lib/api/sources.ts`

以 Source 创建为例，前端如何触发命令：

```typescript
create: async (data: CreateSourceRequest & { file?: File }) => {
  const formData = new FormData()
  
  // 序列化字段
  formData.append('type', data.type)
  formData.append('notebooks', JSON.stringify(data.notebooks))
  formData.append('async_processing', String(data.async_processing ?? false))
  
  if (dataWithFile.file instanceof File) {
    formData.append('file', dataWithFile.file)
  }
  
  const response = await apiClient.post<SourceResponse>('/sources', formData)

```

**关键点**：
- 使用 `FormData` 支持文件上传
- 复杂类型（数组）通过 `JSON.stringify()` 序列化
- `async_processing` 标志控制是否使用异步命令模式

### 3. 命令状态查询

**文件**: `frontend/src/lib/api/insights.ts`

前端通过轮询获取命令执行状态：

```typescript
getCommandStatus: async (commandId: string) => {
  const response = await apiClient.get<CommandJobStatusResponse>(
    `/commands/jobs/${commandId}`
  )
  return response.data
},

waitForCommand: async (
  commandId: string,
  options?: { maxAttempts?: number; intervalMs?: number }
): Promise<boolean> => {
  const maxAttempts = options?.maxAttempts ?? 60  // 默认60次
  const intervalMs = options?.intervalMs ?? 2000   // 默认2秒间隔
  
  for (let i = 0; i < maxAttempts; i++) {
    const status = await insightsApi.getCommandStatus(commandId)
    if (status.status === 'completed') return true
    if (status.status === 'failed' || status.status === 'canceled') return false
    await new Promise(resolve => setTimeout(resolve, intervalMs))
  }
  return false
}
```

## 后端架构

### 1. API 路由层

**文件**: `api/routers/commands.py`

提供命令相关的 REST API 端点：

| 端点 | 方法 | 功能 |
|------|------|------|
| `/api/commands/jobs` | POST | 提交命令到后台执行 |
| `/api/commands/jobs/{job_id}` | GET | 查询命令执行状态 |
| `/api/commands/jobs` | GET | 列出所有命令任务 |
| `/api/commands/jobs/{job_id}` | DELETE | 取消运行中的命令 |

**请求模型**：


**响应模型**：
```python
class CommandJobResponse(BaseModel):

class CommandJobStatusResponse(BaseModel):
```

### 2. 命令服务层

**文件**: `api/command_service.py`

封装 `surreal_commands` 库，提供统一的服务接口：

```python
class CommandService:
    @staticmethod
    async def submit_command_job(
        module_name: str,      # 实际是 app_name，如 "open_notebook"
        command_name: str,     # 命令名，如 "process_source"
        command_args: Dict[str, Any],
        context: Optional[Dict[str, Any]] = None,
    ) -> str:
        # 1. 导入命令模块以确保注册
        import commands.podcast_commands  # noqa: F401
        
        # 2. 调用 surreal_commands 提交命令
        cmd_id = submit_command(
            module_name,    # app name
            command_name,   # command name
            command_args,   # input data
        )
        
        # 3. 返回命令ID
        return str(cmd_id)

    @staticmethod
    async def get_command_status(job_id: str) -> Dict[str, Any]:
        status = await get_command_status(job_id)
        return {
            "job_id": job_id,
            "status": status.status if status else "unknown",
            "result": status.result if status else None,
            "error_message": getattr(status, "error_message", None),
            "progress": getattr(status, "progress", None),
        }
```

### 3. 命令定义层

**文件**: `commands/source_commands.py` (示例)

使用 `@command` 装饰器定义命令：

```python
from surreal_commands import CommandInput, CommandOutput, command

class SourceProcessingInput(CommandInput):
    source_id: str
    content_state: Dict[str, Any]
    notebook_ids: List[str]
    transformations: List[str]
    embed: bool

class SourceProcessingOutput(CommandOutput):
    success: bool
    source_id: str
    embedded_chunks: int = 0
    insights_created: int = 0
    processing_time: float
    error_message: Optional[str] = None

@command(
    "process_source",           # 命令名
    app="open_notebook",        # 所属应用
    retry={                     # 重试策略
        "max_attempts": 15,
        "wait_strategy": "exponential_jitter",
        "wait_min": 1,
        "wait_max": 120,
        "stop_on": [ValueError, ConfigurationError],  # 不重试的错误类型
    },
)
async def process_source_command(
    input_data: SourceProcessingInput,
) -> SourceProcessingOutput:
    start_time = time.time()
    
    # 1. 加载转换配置
    transformations = []
    for trans_id in input_data.transformations:
        transformation = await Transformation.get(trans_id)
        transformations.append(transformation)
    
    # 2. 更新源记录，关联命令ID
    source = await Source.get(input_data.source_id)
    source.command = ensure_record_id(input_data.execution_context.command_id)
    await source.save()
    
    # 3. 执行实际处理（调用 LangGraph）
    result = await source_graph.ainvoke({
        "content_state": input_data.content_state,
        "notebook_ids": input_data.notebook_ids,
        "apply_transformations": transformations,
        "embed": input_data.embed,
        "source_id": input_data.source_id,
    })
    
    # 4. 返回结果
    processing_time = time.time() - start_time
    return SourceProcessingOutput(
        success=True,
        source_id=str(result["source"].id),
        insights_created=len(await result["source"].get_insights()),
        processing_time=processing_time,
    )
```

```python
@staticmethod
async def submit_command_job(
    module_name: str,
    command_name: str,
    command_args: Dict[str, Any],
    context: Optional[Dict[str, Any]] = None,
) -> str:
    # 确保命令模块已导入（注册到 surreal_commands 注册表）
    try:
        import commands.podcast_commands  # noqa: F401
    except ImportError as import_err:
        logger.error(f"Failed to import command modules: {import_err}")
        raise ValueError("Command modules not available")
    
    # 调用 surreal_commands 提交命令
    cmd_id = submit_command(
        module_name,    # app name: "open_notebook"
        command_name,   # command name: "process_source"
        command_args,   # input data
    )
    
    # 转换 RecordID 为字符串
    if not cmd_id:
        raise ValueError("Failed to get cmd_id from submit_command")
    cmd_id_str = str(cmd_id)
    
    logger.info(
        f"Submitted command job: {cmd_id_str} for {module_name}.{command_name}"
    )
    return cmd_id_str
```

#### 步骤 4：命令执行（surreal_commands 内部）

`surreal_commands` 库处理：

1. **注册查找**: 在注册表中查找 `open_notebook.process_source`
2. **持久化**: 在 SurrealDB 中创建 `command` 记录
3. **状态流转**:
   - `queued`: 已入队，等待执行
   - `running`: 正在执行
   - `completed`: 执行成功，结果存入 `result` 字段
   - `failed`: 执行失败，错误信息存入 `error_message`

### 2. 重试策略配置

`@command` 装饰器支持丰富的重试配置：

```python
@command(
    "process_source",
    app="open_notebook",
    retry={
        "max_attempts": 15,                    # 最多重试15次
```

- 网络临时故障

## 异步任务模式

### 模式对比

| 特性 | 同步模式 | 异步模式 |
|------|---------|---------|
| 阻塞行为 | 阻塞 HTTP 请求 | 立即返回 |
| 超时控制 | 5 分钟硬编码 | 无限制（后台运行） |
| 状态查询 | 无需查询 | 需轮询 `/commands/jobs/{id}` |
| 适用场景 | 快速操作 | 耗时操作（LLM 调用、文件处理） |
| 前端体验 | 加载中等待 | 可继续操作，后台处理 |

### 异步模式的优势

1. **用户体验**：上传大文件后可立即操作，无需等待
2. **可靠性**：支持重试机制， transient error 自动恢复
3. **可观测性**：可随时查询执行状态和进度
4. **资源管理**：worker 进程可独立扩展

### 状态流转

```
                    ┌──────────────┐
                    │   queued     │  已入队，等待 worker  pickup
                    └──────┬───────┘
                           │
                           ▼
                    ┌──────────────┐
              ┌────▶│   running    │  正在执行
              │     └──────┬───────┘
              │            │
              │            │
    ┌─────────┴────┐  ┌────┴─────────┐
    │   failed     │  │  completed   │
    │ (执行失败)    │  │  (执行成功)   │
    └──────────────┘  └──────────────┘
           │
           ▼
    ┌──────────────┐
    │  (可重试)    │  如果配置了重试策略
    └──────────────┘
```

## 总结

### 核心架构要点

1. **两层命令系统**：
   - 前端 `CommandPalette.tsx`：纯 UI 交互，本地导航
   - 后端 `surreal_commands`：异步任务队列，耗时操作

2. **序列化机制**：
   - 前端：`FormData` + `JSON.stringify()` 复杂类型
   - 后端：Pydantic `BaseModel` 自动解析 + `model_dump()` 序列化

3. **调用路径**：
   ```
   前端 UI → sourcesApi.create() → apiClient.post()
       ↓
   后端 POST /api/sources → CommandService.submit_command_job()
       ↓
   surreal_commands.submit_command() → SurrealDB 持久化
       ↓
   Worker 进程异步执行 → 状态更新
       ↓
   前端轮询 GET /api/commands/jobs/{id} → 获取结果
   ```

4. **关键设计决策**：
   - 命令通过 `@command` 装饰器自动注册
   - 支持灵活的重试策略（指数退避、错误分类）
   - Source 记录与 Command 记录通过外键关联
   - 同步/异步双模式支持（异步为推荐模式）
